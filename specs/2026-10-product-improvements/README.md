# AIダイジェスト 利便性向上の機能提案と設計文書

2026年10月4日のGitHub既存コードを確認し、毎朝のニュースを「短時間で聴く」「圏外でも使う」「後から探す」ための改善を提案します。まず音声と配信状態を整え、再生再開、時間に合わせたニュース選択、検索、ダウンロード管理を加える方針です。

これは**提案段階の初版 0.1**です。今回作成したのは文書だけで、以下の新機能はまだ実装していません。機能の採否、開発日程、予算は未確定です。現行のGemini音声配信とは区別してください。

## 最初に実装したいこと

| 順番 | 提案 | ユーザーにとっての利点 |
|---|---|---|
| 1 | 配信状態の明示と初回音声デモの修正 | 「今日は未配信」「音声だけ準備中」「通信失敗」を区別でき、最初の試聴で迷わない |
| 2 | 再生位置の保存、15秒送り戻し、停止タイマー | 中断しても聴いた場所から続けられる |
| 3 | 今日の音声をまとめてダウンロード | 通勤前に保存し、圏外で確実に聴ける |
| 4 | 3分・5分・10分のニュース選択 | 空き時間に合う記事だけを選べる。指定時間を埋めるための水増しはしない |
| 5 | 保存記事・過去記事の検索と除外設定 | 読み返したい情報を探し、興味の薄い情報を減らせる |

次段階では、コレクションとメモ、用語解説、週次振り返り、Web版の音声再生を提案しています。アクセシビリティは各段階の受入条件に含めます。

## 調査の基準

- 対象: [Takuya-ops/ai-morning-digest](https://github.com/Takuya-ops/ai-morning-digest)。SIGNAL 10は対象外。
- 基準コミット: [`a472fa105ab634094604210dfe0c8fcc83532408`](https://github.com/Takuya-ops/ai-morning-digest/tree/a472fa105ab634094604210dfe0c8fcc83532408)。後続の変更があれば実装前に再照合する。
- 構成: Node.jsの日次処理、GitHub PagesのWeb/PWA、SwiftUIのiOSアプリ、SQLite、GitHub Releasesの配信音声。
- 10月4日配信の確認: TOP10のGemini音声URLは10件。`summaryStyles`、`ttsText`、非空の`faq`は0件、`aiGenerated=true`も0件。Gemini TTSへの変更だけでは日本語要約やQ&Aは増えない。
- 確認方法: GitHub mainとの一致、ソースコード、配信JSON、直前の本番Actions結果。利用者インタビュー、継続率調査、全端末の操作検証は行っていない。利便性の評価は仮説である。

## 現状から分かった注意点

既存の保存、既読、興味トピック、通知、オフライン閲覧、Widget、Siri、X投稿案は新規機能として数えていません。一方、音声の秒単位の再開、音声保存容量の管理、ライブラリ検索は未実装です。

初回案内の「読み上げを試す」は音声URLを持たないデモ記事を現在選択中のプレイヤーへ渡します。既定がGeminiの新規利用者では、遠隔音声の未配信エラーになるコード経路があります。さらに先読み側にはNanamiを既定とする残存処理があります。これらは設計上の先行修正項目です。今回そのコードは変更していません。
